# ASAN Frontend

ASAN (**آسان**) is a low‑code platform for building **fully customized webshop frontends**. This repository contains the **frontend client** of ASAN, which dynamically adapts to configurations defined in the ASAN DSL and renders a modern e‑commerce experience.

---

## 📖 Overview

The ASAN frontend is a **React + TypeScript + Vite** project designed for speed, flexibility, and modularity. Instead of hard‑coding shop content, it consumes **JSON output generated by the ASAN DSL compiler** and builds the webshop accordingly.

**Key features:**

- Dynamic rendering of categories, products, and filters from DSL‑generated JSON.
- Modular UI with reusable components (cards, sliders, search, filters).
- Cart management with global state via React Context.
- Fully deployable on **Vercel** (see `vercel.json`).
- Extensible for custom themes and layouts.

## 📂 Project Structure

```
ASAN-frontend/
├── index.html                # Entry HTML
├── vite.config.ts            # Vite configuration
├── package.json              # Dependencies & scripts
├── vercel.json               # Vercel deployment config
├── public/
│   └── data/webshop.json     # DSL-generated webshop definition
├── src/
│   ├── App.tsx               # Root app component
│   ├── main.tsx              # React entry point
│   ├── assets/               # Static images & assets
│   ├── components/           # Reusable UI components
│   ├── contexts/             # Global contexts (e.g. CartContext)
│   ├── hooks/                # Custom React hooks
│   ├── pages/                # All main pages
│   ├── types/                # TypeScript type definitions
│   └── utils/                # Helper functions
```

### Pages

- **Homepage.tsx** → Dynamic landing page with product sliders & featured sections.
- **ProductsPage.tsx** → Product listing with filtering & sorting.
- **ProductDetail.tsx** → Individual product view.
- **CartManagementPage.tsx** → Full cart management workflow.
- **SearchResults.tsx** → Search results with autocomplete.
- **AboutUsPage.tsx** → Static information page.
- **FAQ.tsx** → Frequently asked questions page.

### Components (selected)

- `Header`, `Footer`, `MegaMenu` → Navigation & layout.
- `ProductCard`, `ProductSlider`, `ImageSlider` → Product showcasing.
- `Cart`, `SortDropdown`, `DynamicFilter` → E‑commerce functionality.
- `SearchBox`, `SearchAutocomplete` → Smart search experience.

### Contexts

- **CartContext** → Manages cart state across the app.

### Hooks

- **useCategoryData.ts** → Loads and structures category data from JSON.
- **UseWebshopData.ts** → Loads the DSL‑generated webshop definition.

### Utils

- **theme.ts** → Theming and styling helpers.
- **urlUtils.ts** → URL construction/parsing utilities.
- **searchUtils.ts** → Product search logic.

---

## 🔗 Backend Integration

- The frontend relies on **DSL‑generated JSON files** served from `public/data/webshop.json`.
- Future integration with a backend API can replace the JSON file (e.g., a Flask/Postgres backend or other service).
- Endpoints should deliver shop metadata, product details, and category trees in the same schema as `webshop.json`.

## 🚀 Getting Started

### Prerequisites

- Node.js >= 18
- npm or yarn

### Installation

```bash
# Clone repository
git clone https://github.com/your-org/ASAN-frontend.git
cd ASAN-frontend

# Install dependencies
npm install
```

### Development

```bash
# Start dev server
npm run dev
```

The app runs at [http://localhost:5173](http://localhost:5173).

### Build

```bash
npm run build
```

Output is generated in the `dist/` folder.

### Preview Production Build

```bash
npm run preview
```

---

## 🎨 Customization

1. **DSL Integration**: Replace or update `public/data/webshop.json` with new DSL‑generated output.
2. **Styling**: Modify `utils/theme.ts` or extend Tailwind config.
3. **Components**: Extend existing components in `src/components/` to add custom widgets.
4. **Pages**: Add or remove static pages in `src/pages/`.

---

## 📦 Deployment

ASAN frontend is ready for **Vercel** deployment.

```bash
vercel --prod
```

Alternatively, serve the built `dist/` folder with any static hosting service.
